# ファイルアクセス

スクリプトがファイルを読み書きできるということは、走らせただけでパソコンの中を覗かれるかもしれない、ということでもあります。人からもらったスクリプトを試すたびに、見られたくない書類まで開いていないか中身を読んで確かめるのは、さすがに大変です。

なので、好きな場所を指定する手段そのものを用意していません。触れるのは、自分で選んだファイルか、いま開いているドキュメントの隣だけです。

## 入口は 3 つ

```swift
if let fs = paplico.getFileSystem() {
	fs.documentDirectory              // ドキュメントの隣
	await fs.openFiles()              // 選んでもらった既存ファイル
	await fs.saveFile(fileName: "…")  // 選んでもらった保存先
}
```

`openFiles` と `saveFile` は、呼ぶたびに、いつものファイルを選ぶ画面が開きます。そこで選ばれたファイルだけが `AutomationFile` として返ってきます。選ばれなかったファイルには、たとえ名前を知っていても手が出せません。キャンセルされたときは、`openFiles` なら空の配列、`saveFile` なら `nil` が返ります。

`documentDirectory` だけはダイアログが出ません。ドキュメントを開いた時点で、その親フォルダを使う許可がもう取れているからです。書き出し先のフォルダを作るのも、いちいち確認しません。

フォルダ自身は読み書きしません。できるのは、下の階層をたどることと、そこにあるファイルを取り出すことの 2 つだけです。

```swift
if let dir = fs.documentDirectory {
	let renders = await dir.createDirectory(path: "exports/renders")
	if let log = await renders.file(path: "log.txt", create: true) {
		await log.writeText(content: "done")
	}
}
```

`createDirectory` は `mkdir -p` と同じで、途中のフォルダが足りなければまとめて掘りますし、既にあってもエラーにはなりません。返ってくるのは掘った先のフォルダなので、そこからさらに `file` や `createDirectory` を続けられます。

`file` はそこにあるファイルを取り出すだけで、勝手には作りません。無ければ `nil` が返ります。新しく作りたいときだけ `create: true` を付けてください。付ければ、足りない親フォルダも一緒に掘ります。既にあるファイルに付けた場合は、そのまま中身を残して開きます。

```swift
if let existing = await dir.file(path: "note.txt") {
	print(await existing.readText())
} else {
	print("まだありません")
}
```

返ってくるファイルは、`openFiles` や `saveFile` で受け取るものと同じものです。

パスの区切りは `/` でも `\` でもかまいません。どちらで書いても、動かしている環境に合わせて読み替えられます。

## 渡したパスがどう調べられるか

`documentDirectory` に渡す `path` は、ドキュメントのあるフォルダから見た道順として読まれます。ここを何も見ずに通してしまうと、`..` をいくつか並べるだけでフォルダの外まで出ていけてしまいます。そうならないよう、次の順で調べています。

1. `/` から始まる書き方や `..` がひとつでも混ざっていたら、そこで断ります。
2. 途中のフォルダを 1 段ずつ辿りながら、実体を辿った先がまだフォルダの中に収まっているかを、毎回確かめます。
3. 書き込みのついでに親フォルダを作った場合も、作った直後にもう一度同じ確認をします。

2 段目があるのは、ショートカット（シンボリックリンク）のためです。`exports` という名前のフォルダが、実はまったく別の場所への近道だった、ということがあります。名前だけ見ればドキュメントの隣にいるのに、書き込んだ先は遠くのフォルダ、という具合です。近道の先まで辿ってから見比べれば、この抜け道はふさげます。

ファイルのほうには、そもそも道順を渡せません。読み書きの相手はそのファイル自身に決まっていて、隣を指す余地がないからです。`file` で取り出した 1 つ下のフォルダのファイルも、`openFiles` で選ばれたファイルも、この点では同じ扱いになります。

## いつまで有効か

許可はドキュメントのセッションにひもづいています。別のドキュメントに切り替えると、それまでの許可はまとめて取り消されて、また選び直しになります。前のドキュメントを開いていたときに選んだファイルへ、あとから書き戻すことはできません。

逆に、スクリプトが終わっただけでは取り消されません。同じセッションのあいだなら、一度選んだファイルに別のスクリプトから書き込めます。

## ブラウザ版では使えません

`getFileSystem()` が中身を返すのはデスクトップ版だけで、ブラウザ版ではいつも `nil` です。ブラウザには「ドキュメントの隣」にあたる場所がなく、確認なしで書き込む仕組みを安全に作れないためです。

ファイルを使うスクリプトを配るなら、`nil` だったときの道も書いておくと親切です。

```swift
guard let fs = paplico.getFileSystem() else {
	await paplico.prompt.alert(message: "このスクリプトはデスクトップ版でのみ動作します")
	return
}
```

スクリプトの保存にも同じ線が引いてあって、ブラウザ版では組み込みのものを動かせても、新しく追加することはできません。

## 画像など、文字以外を書くとき

画像や音声のように文字ではないファイルは、`writeBytes` に数値の並びとして渡します。ここに入れられるのは 0 から 255 までの整数だけです。それをはみ出した値や小数が混ざっていると、ファイルに触る前にエラーになります。書きかけのファイルが残ってしまわないよう、確認のほうが先です。

```swift
await file.writeBytes(content: [72, 101, 108, 108, 111])  // OK
await file.writeBytes(content: [256])                     // エラー
```

文字を書くだけなら `writeText` で済みます。数値に直す作業は中でやってくれます。
