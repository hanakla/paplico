# ブラシ動特性と確定処理

> [!NOTE]
> **前提ページ:** [ストローク入力と曲線フィッティング](/devdocs/brush-system/input-and-fitting)

ブラシの太さや濃さは、ペンが通った座標だけでは決まらない。各入力点の時刻から速度を求め、ブラシ設定のcurveを評価して、各Dabのサイズ、flow、spacingを変化させる。

入力中のストロークは毎frame変化する。確定後のストロークはYjsドキュメントに残り、同じ幅を後から再現できる必要がある。この違いを吸収するのが、raw pointの `deltaTime`、2本の速度EMA、property curve、`bakeStrokeWidthProfile` である。

raw pointはデバイスから受け取った入力点である。座標、筆圧、傾き、ストローク開始からの経過時間を持つ。segmentはraw pointsをfitしたcubic Bézier曲線である。Dabはsegmentに沿って置くブラシ先端の描画単位である。

## 入力から再描画まで

```mermaid
flowchart TD
    A["Pointer samples"] --> B["raw points<br/>x, y, pressure, deltaTime"]

    I --> J["StrokeWidthProfileBuilder"]

    K --> F

    F -->|pointerup| L["same fit without input knots + same widths"]

    M --> N["Yjs transaction"]

    O --> P["RenderScheduler"]

```

プレビューと確定Pathは同じfitから作る。確定Pathはそのfitからinput knotを除いたsegment列と、プレビューと同じ幅プロファイルを持つ。

## 時刻をraw pointへ残す

`PenTool.onPointerDown` は `pointerdown` イベントの `timeStamp` をストローク開始時刻として保持する。最初の `pointermove` のcoalesced sampleはハンドラより前の時刻を持つためである。最初のraw pointの `deltaTime` は0ミリ秒である。

`getCoalescedEvents()` から受け取ったsampleは次の式を使う。結果が負になる場合は0へclampする。

```text
deltaTime = max(sample.timeStamp - strokeStartTime, 0)
```

coalesced eventがない `pointermove` は次の式を使う。

```text
deltaTime = event.timeStamp - strokeStartTime
```

`deltaTime` の単位はミリ秒である。時計originを変換する別の正規化関数はない。`PointerEvent.timeStamp` と `performance.now()` が持つ時計をそのまま使う。

timed Dab対応ブラシは、ペンが動かない間も25ミリ秒周期で最後のraw pointを複製する。座標と入力属性は変えない。`deltaTime` だけを現在の経過時間へ進める。

## DabEvaluatorが速度を求める

raw pointを追加する段階では速度を計算しない。ダブエンジンの `DabEvaluator.evaluateDabs` がsegment上を歩き、前sampleからの距離と時間差を求める。

```text
stepDist = hypot(x - previousX, y - previousY)
stepTime = max(deltaTime - previousDeltaTime, 0)
stepVelocity = stepDist / stepTime
```

距離の単位はworld unitである。速度の単位はworld unit per millisecondである。`stepTime` が0.001ミリ秒より大きい場合だけ、速度EMAを更新する。

入力間隔の揺れをそのままブラシへ伝えると、同じ手の動きでもDabが安定しない。`DabEvaluator` は短期変化を追うfast EMAと、長期傾向を残すslow EMAを並行して更新する。

```text
alpha = 1 - exp(-stepTime / tau)
velocity += (stepVelocity - velocity) * alpha
```

| 系列 | 内部状態 | 既定時定数 | 正規化出力 |
|---|---|---:|---|
| fast | `velFast` | 25 ms | `speedFine` |
| slow | `velSlow` | 110 ms | `speedGross` |

通常のストローク開始では、fast EMAとslow EMAを接触速度の窓から求めた値でseedする。seedする値は、各EMAがその窓の内側で到達する最大値である。窓の扱いは「プレビューと確定で幅を共有する」で説明する。`pathStart` が0より大きいfragmentでは、最初のsegmentの長さを所要時間で割った速度で両方のEMAをseedする。`resume` stateを渡した評価は、前のchunkのEMAをそのまま引き継ぐ。

### speedRef

2本のEMAは `speedRef` で割って0から1のcurve入力へ変換する。

```text
speedFine = min(velFast / speedRef, 1)
speedGross = min(velSlow / speedRef, 1)
```

`inputDynamics.speedRef` が設定されていればその値を使う。未設定なら、ブラシのbase sizeから自動値を求める。

```text
speedRef = clamp(sizeBase * 0.06, 0.5, 2.0)
```

速度が `speedRef` 以上になると `speedFine` と `speedGross` は1へ飽和する。`inputDynamics.speedFineTau` と `inputDynamics.speedGrossTau` はそれぞれの時定数を上書きする。brush v2へのmigrationは、これら3つの値のうち正数だけを設定として残す。`evaluateDabs` は値を検査しない。

### accelと静止時の減衰

`accel` はfastとslowの差に方向転換量を加えた値である。

```text
turnAmount = clamp((1 - dot(previousDirection, direction)) * 0.5, 0, 1)
accel = min(abs(velFast - velSlow) / speedRef * 0.8 + turnAmount, 1)
```

segment長が0.001 world unit未満な場合は静止segmentとして扱う。fastとslowの目標速度を0にし、segmentの経過時間に応じてEMAを減衰させる。

## 速度をproperty curveへ渡す

`speedFine`、`speedGross`、`accel` は0から1のbrush inputである。`DabEvaluator` は各Dabをemitする直前に、現在の速度入力でsize、flow、spacingなどのpropertyを評価する。

`bakeBrushProperties` はストロークごとにcurveをlookup tableへ変換する。`evalBrushProperty` は同じpropertyに接続されたcurve出力を合計する。size、flow、spacingはscale domainである。

```text
factor = clamp(1 + curveOutputSum, 0, 8)
value = clamp(base * factor, propertyMin, propertyMax)
```

各Dabの `speedFine` と `accel` は `motionSpeed` と `motionAccel` としてinstance bufferにも入る。wet brush shaderはこれらの値をmoisture fieldへ渡す。

速度入力を計算するのはdab engineである。ribbon engineのcurve評価はpressure、`strokeT`、fadeを設定する。`speedFine` と `speedGross` はneutral値の0に残る。geometric engineは専用のpressure幅式を使う。

## sizeBySpeedとpoolingの互換変換

dab engineに `sizeBySpeed` と `pooling` の専用分岐はない。brush v2以前のドキュメントを開くとき、migrationがこれらの値を `speedFine` 入力のproperty curveへ変換する。

### sizeBySpeed

`sizeBySpeed` を `k` とする。変換後のsize curveは次の2点である。

```text
[[0, 0], [1, -k]]
```

正規化速度 `s` に対するcurve寄与は `-k * s` になる。他のsize curveがなければ、実効値は次のようになる。

```text
size = baseSize * clamp(1 - k * s, 0, 8)
```

速度0でbase sizeを使う。速度が `speedRef` 以上になると `baseSize * (1 - k)` まで小さくなる。

### pooling

`pooling` を `p` とする。`poolingSizeRatio` を `r` とする。変換後は3本のcurveに分かれる。

| property | curve | 正規化速度 `s` に対する寄与 |
|---|---|---|
| spacing | `[[0, -0.6p], [1, 0]]` | `-0.6p(1-s)` |
| size | `[[0, 0.3pr], [1, 0]]` | `0.3pr(1-s)` |
| flow | `[[0, 0.5p(1-r)], [1, 0]]` | `0.5p(1-r)(1-s)` |

低速域ではDab間隔が狭くなる。サイズとflowは増える。速度が `speedRef` へ達するとpooling寄与は0になる。最終値は各propertyのregistry範囲へclampする。flowの上限は1である。

## ライブプレビューの速度

`IncrementalStrokeFitter` はraw pointsからプレビュー用segmentを作る。smooth方式は座標と同じGaussian kernelで `deltaTime` も平滑化する。先頭と末尾の時刻はraw値を保つ。筆圧は平滑化せずraw値のまま通す。サイズの幅プロファイルは補正済みraw samplesから生成する。

曲線fitが複数の入力点を1本のsegmentへまとめると、端点時刻の線形補間だけでは途中の速度変化が消える。ライブtailは、線形時刻から8ミリ秒、または線形筆圧から0.05を超えて外れる入力点にinput knotを追加する。最大16個である。de Casteljau subdivisionはgeometryを変えない。segment端の時刻と筆圧の密度だけを増やす。

ダブエンジンのプレビューは、このsegment列と幅プロファイルを `evaluateDabs` へ渡す。buildupプレビューは `LiveDabAccumulator` で確定済みprefixの評価結果を再利用する。確定済みDabは評価時の幅を保つ。プロファイルの `t` はraw polylineの全長で正規化している。ストロークが伸びると、fit後の弧長比に対して少しずれる。これは `pathT` と同じく許容する近似である。確定済み弧長より手前のプロファイル点が書き換わった場合は、prefixを捨てて評価し直す。接触速度の窓が閉じるまでは何も凍結しない。

prefix再利用は、過去部分の評価が全長に依存しないbuildupプレビューに限る。`strokeT` カーブ、along方向の色、終端tipがある場合は全体を評価する。結果はframe poolのGPU bufferへ送る。washプレビューも全体を評価する。

## プレビューと確定で幅を共有する

`PenTool.createStrokePath` はプレビュー更新時に幅プロファイルを作る。pointerup後は同じfitからinput knotを除いたsegment列と同じ幅プロファイルでPathを作る。幾何と幅を確定時に再計算しない。

スタイラスは接触してから動き出すまで低速で留まる。`DabEvaluator` はpointerdownから200ミリ秒の窓の中で、fineとgrossの速度EMAをそれぞれがその窓で到達した最大値で下限クランプする。速度入力だけが対象で、筆圧は触らない。窓が閉じた後は各EMAが自分の値から続く。意図した減速は太いまま残る。定数は `CONTACT_SPEED_WINDOW_MS` である。窓の最大値はその評価に渡されたsegment列から求める。knot付きのプレビューとknotなしの確定では、速度駆動のflowやspacingが窓の中で少し違いうる。幅は焼き込んだプロファイルから読む。この差は幅には出ない。

`StrokeWidthProfileBuilder` はダブエンジンの評価状態を保持する。通常は追加されたraw samplesだけを評価する。プロファイルはraw polylineの弧長距離をキーに後ろへ伸びる。線形補間で0.01以内に再現できるDabは保存しない。末尾のDabと、polylineの終端に置く同じ幅比の点は暫定である。次の更新で置き換わる。接触速度の窓が閉じるまでは毎回最初から評価する。始点筆圧の補正で既存sampleが変わった場合も最初から評価する。`strokeT` カーブがある場合とダブ以外のエンジンでは `bakeStrokeWidthProfile` で全体を評価する。

`PenTool.createStrokePath` は、この距離キーのプロファイルをraw polylineの全長で割って `strokeWidths` にする。レンダラはfit後の弧長比で読む。プロファイルの両端は描画するsegment列の両端に一致する。

確定segmentはfitした曲線の端点に入力時刻を持つ。そのsegmentだけを幅評価へ使うと、1本のsegment内の速度変化は線形化する。`bakeStrokeWidthProfile` はraw pointsを直線segment列へ変換し、入力時のpressureと `deltaTime` を保ったまま幅を評価する。

`bakeStrokeWidthProfile` のdab routeは実際の `evaluateDabs` を実行する。各Dabの `sizeX / 2` をpath上のhalf widthとして補間する。

path上の0から1を256分割する。端点を含む257点で次の幅比を評価する。

```text
widthRatio = halfWidth / (size.base / 2)
```

全比率が先頭値から0.001以内なら幅は一定である。この場合はprofileを保存しない。変化がある場合は、線形補間誤差が0.01以内になるまでprofileを簡略化する。出力は左右が同値の `StrokeWidthPoint[]` である。

プレビューと確定Pathは `strokeWidths` に同じprofileを持つ。profileを作った場合は `strokeWidthsBaked` がtrueになる。確定PathのDabを再生成するときはsize curveをneutralizeする。保存した幅比で `sizeX` と `sizeY` をscaleする。size curveによる幅変化は二重適用しない。

size以外のspeed curveはprofileへ焼き込まない。共有するsegmentの時刻を使って描画時に再評価する。

## Yjsへ保存する

確定Pathには中心線の `segments`、描画設定の `filters`、ベイクした `strokeWidths`、`strokeWidthsBaked` が入る。`PenTool` はこのPathを `context.strokeComplete` へ渡す。

Paplicoの `strokeComplete` は一時overrideを消し、`commands.addPath` を呼ぶ。`PaplicoCommands.addPath` はreadonly状態、現在のlayer、lock状態を確認する。書き込み可能な場合はYjsトランザクション内で `YjsProvider.addElement` を呼ぶ。同じトランザクション内で `moveIntoEditingScope` も呼ぶ。グループなどの編集スコープに入っている場合に、Pathをそのスコープへ移すためである。

`YjsProvider.addElement` はPath本体を `yObjects` へ保存する。対象layerの `elementIds` にPath IDを追加する。Pathとlayer参照は同じYjs transactionで更新する。

`addPath` の後、`strokeComplete` は `spatialIndex.invalidateBounds` でPathのboundsを計算し直す。`selectStrokeAfterDraw` が有効な場合はそのPathを選択する。

`strokeComplete` が戻った後、`PenTool` は描画状態をidleへ戻す。`previewUpdate(null)` はtransient previewを削除する。

```mermaid
sequenceDiagram
    participant Tool as PenTool
    participant Session as BrushStrokeSession
    participant Commands as PaplicoCommands
    participant Yjs as YjsProvider
    participant Changes as DocumentChangeSubscriber

    Tool->>Session: commit()
    Session-->>Tool: raw points
    Tool->>Session: getCommitSegments()
    Session-->>Tool: fit without input knots
    Tool->>Tool: build Path with new ID and same widths
    Tool->>Commands: addPath(committed Path)
    Commands->>Yjs: addElement in transaction
    Yjs-->>Changes: full document sync
    Changes->>Scheduler: invalidate document without change set
    Scheduler->>Scheduler: coalesce until next animation frame
```

## 確定後の再描画

`addElement` は `yObjects` とlayerの `elementIds` を同じトランザクションで変える。objectとlayerが同時に変わった更新を、`YjsProvider.syncYjsToValtio` はfull syncとして扱う。`extractDocumentFromYDoc` でdocument全体を作り直し、`onDocumentUpdate` へ渡す。Paplicoはstoreのdocumentを差し替える。`SpatialIndex` はこの差し替えを購読していて、`rebuildAllIndices` で全indexを作り直す。続いて `DocumentChangeSubscriber.syncFullDocument` がツールUIを更新する。

最後に `DocumentChangeSubscriber.onSyncApplied` がdocument invalidationを出す。full syncは変更した要素のIDを持たない。このためchange setを渡さない。

`RenderScheduler.markDirty` は同じframe内のdirty reasonとelement IDをまとめる。change setのないdocument変更を受けると、そのframeの変更追跡を破棄する。render callbackにはchange setを渡さない。document変更はfull render strategyである。次の `requestAnimationFrame` でrender callbackを呼ぶ。

確定したdab strokeは `evaluateDabs` の結果をStampCacheへ保存する。後続のpanとzoomはGPU bufferを再uploadすることがある。Dabのproperty評価は繰り返さない。

描画モードとGPU処理の詳細は[ブラシレンダリング](/devdocs/renderer/brush)を参照。
