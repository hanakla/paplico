# パス描画フロー

Paplicoにおけるパス要素（Path）は、3次ベジエ曲線の配列として表現される。本ページでは、このベジエ曲線データがどのようにGPU描画コマンドに変換されるかを、データ構造からシェーダー実行まで順を追って解説する。

> [!NOTE]
> このページは[要素レンダリング](/devdocs/renderer/elements)および[パイプライン概要](/devdocs/renderer/pipeline)の内容を前提とする。

## 全体フロー

パス描画は4段階で処理される。GPU に渡るのは三角形メッシュではなく、CPU で求めた**被覆率**（ピクセルのうち形状が占める面積の割合）である。

## データ構造

パス要素は `CubicBezierSegment` の配列で構成される。各セグメントは3次ベジエ曲線の4つの制御点を持つ:

| フィールド | 説明 |
|---|---|
| `start` | 開始アンカー（最初のセグメント以外は省略され、前セグメントの `end` を継承） |
| `cp1` | 制御点1。**開始アンカーからの相対オフセット** |
| `cp2` | 制御点2。**終了アンカーからの相対オフセット** |
| `end` | 終了アンカー（ワールド座標） |
| `isMoved` | 新しいサブパスの開始を示すフラグ |
| `isClosed` | サブパスの閉じフラグ |
| `startPressure` / `endPressure` | セグメント始点・終点での筆圧（0-1） |

`cp1` と `cp2` を相対オフセットとして保存する理由は、アンカー点の移動時に制御点が自動的に追従するため、座標変換やアニメーション時の安定性が向上するためである。実際の描画時には `resolveSegment()` でワールド座標に変換される:

```typescript
// cp1: start からの相対 → ワールド座標
cp1_world = { x: start.x + cp1.x, y: start.y + cp1.y }
// cp2: end からの相対 → ワールド座標
cp2_world = { x: end.x + cp2.x, y: end.y + cp2.y }
```

## アウトライン: 要素ローカル空間での平坦化

フラッテニングとは、ベジエ曲線を十分に細かい直線の列（ポリライン）に近似する処理である。GPU はベジエ曲線を直接ラスタライズできないため、すべてのパス描画はこの段階を経る。

実装は `flattenBezierPath()`（`renderer/geometry/bezierFlatten.ts`）にあり、**de Casteljau の再帰二分割法**を使用する:

1. ベジエ曲線の4制御点 (p0, p1, p2, p3) を受け取る
2. 曲線が十分に「平ら」かを判定（制御点が始点-終点の直線からどれだけ離れているか）
3. 平らでなければ、中点で2つのベジエ曲線に分割して再帰処理
4. 平らなら、終点を直線セグメントとして出力

許容誤差は**画面上のピクセル**で決まる。`deviceScaleBucket()` が要素の合成変換とパスのズームから 2 のべき乗の「スケールバケット」を求め、ローカル空間の許容誤差を `0.25px / 2^bucket` にする。こうして曲線は最大ズーム 640 倍でも画面上 0.25px 以内の誤差で追従し、同じバケット内のズームではアウトラインを再計算しない。

結果は `OutlineCache` に要素ごとに保持される。塗りは閉じたポリライン、線は `tessellateStroke()` の三角形リストである。どちらも要素ローカル空間なので、パンや要素の移動では作り直さない。

筆圧情報が必要な場合は `flattenBezierPathWithPressure()` を使用する。この関数は各分割点でのベジエパラメータ `t` を記録し、セグメントの `startPressure` / `endPressure` から圧力を線形補間して返す。

## strip 生成: 被覆率をタイルで積算する

アウトラインは描画先パスのテクセル空間（prebuf、オフスクリーン、マスクアトラス、書き出し先のいずれか）へ変換されてから線分になる。実装は `renderer/geometry/strips/` にあり、Vello GPU の sparse strips 方式を TypeScript に移したものである。

1. **クリップ** — パス矩形の外の線分は捨てる。ただし左側にはみ出た部分は左端へ射影した縦線として残す。右側のピクセルに与える巻き数を保つためである
2. **タイル分配** — 各線分が通る 4×4px タイルを列挙し、`(行, 列)` で基数ソートする。水平線も巻き数は変えないがタイルを作る。頂点の高さで行ごとの巻き数が変わる区間を、空の隙間と区別するためである
3. **面積積分** — タイルを行帯ごとに走査し、線分がピクセル内に作る台形面積を巻き数の変化として積算する。線分の右側のピクセルには線分の高さ分がそのまま加わる
4. **strip 出力** — 連続するタイルを 1 本の strip にまとめ、8bit の alpha をスロット列に書く。形状に完全に覆われた隙間は alpha を持たない「fill gap」として幅だけ伸ばす

被覆率は `min(1, |巻き数の積分|)` である。同じ向きで重なる部分は union、逆向きは穴になる。ストロークは `tessellateStroke()` の三角形を全て同じ向きに揃えて流し込むので、結合部や自己交差で重なった三角形も 1 回だけ塗られる。半透明の線が交点で濃くならないのはこのためである。

結果は `StripCache` に `(要素, パス種別)` ごとに保持される。キーは変換の線形部分とサブピクセル位相なので、整数テクセルのパンでは再利用し、ズームや変形の変更で作り直す。

## GPU描画

`StripFrame` がフレーム内の strip インスタンスと alpha ページを集め、submit の直前に 1 回だけアップロードする。描画は strip 1 本につき 1 インスタンスの矩形で、`strip.wgsl` が担当する。

**Vertex Shader:**
1. インスタンスの `x, y, width, height` からパス空間のピクセル矩形を作り、NDC に変換する
2. ビューポートと要素変換を逆に辿り、ペイント用のローカル座標とマスク用のワールド座標を復元する

**Fragment Shader:**
1. 自分のピクセル列に対応するスロットから alpha を `textureLoad` する。dense 領域の外は 1.0
2. `paintCommon.wgsl` の `paintColor()` でペイントを解決する。`gradientType` で分岐し、`0` ソリッド、`1` 線形、`2` 放射状、`3` フリー、`4` メッシュ、`5` パターンを扱う
3. alpha を掛けてから `applyClipMask()` でクリップマスクを適用する

線のグラデーションが `along` / `across` のときは、CPU が三角形の重心座標から画素ごとの `(t, u)` を rg8 の params ページへ書き、フラグメントはそれを読んでストップを引く。

ソリッド色はインスタンスに直接乗る。不透明度の変更は strip を作り直さず、インスタンスの色だけを更新する。

## Stroke: ジオメトリックブラシ

ジオメトリックブラシによるストロークは `tessellateStroke()` で三角形メッシュに変換される。

### テッセレーション処理

1. **半幅計算** — 各頂点で `halfWidth = baseWidth * 0.5 * (1 - sizeByPressure * (1 - pressure))` を算出
2. **可変幅補間** — `strokeWidths` 配列が設定されている場合、Arc-length parameterizationで各点の左右幅を補間
3. **セグメント構築** — 各辺の方向ベクトル (dx, dy) と法線ベクトル (nx, ny) を計算
4. **三角形化** — 各辺について、法線方向に半幅だけ拡張した2つの三角形を生成
5. **Join処理** — 辺の接続部で `lineJoin` 設定に応じた処理:
   - `round`: 扇形の三角形群で丸く接続。分割数はスケールバケットの画面誤差 0.25px から決める
   - `bevel`: 1つの三角形で斜めに接続
   - `miter`: 延長線の交点まで尖らせる（ミターリミット 4.0 超過時はbevelにフォールバック）
6. **Cap処理** — 始点・終点で `lineCap` 設定に応じた処理:
   - `round`: 半円の三角形群
   - `square`: 半幅分の矩形延長
   - `butt`: 延長なし

三角形は互いに重なってよい。strip 生成が非ゼロ巻き数で union を取るため、AA 用のフリンジや内側へのインセットは要らない。

### ダッシュパターン

`applyDashPattern()` がSVG仕様準拠の破線パターンを適用する。フラッテニング済みポリライン上でパターン長を累積し、線分内の正確な位置で補間して分割する。

## Stroke: テクスチャブラシ

テクスチャブラシ（airbrush、pencil等）は `DabEvaluator` でDab列を生成し、`BrushRenderer` から `DabRenderer` がインスタンスドレンダリングする。詳細は[ブラシレンダリング](/devdocs/renderer/brush)ページを参照。

処理の概要:
1. ベジエ曲線上を Arc-length parameterization で等間隔に走査
2. 各スタンプ位置でベジエ曲線を評価し、座標・回転・筆圧・サイズを算出
3. 全スタンプデータを `Float32Array` にパックしてGPUバッファに転送
4. テクスチャ別にバッチ化し、インスタンスドレンダリングで一括描画

## キャッシュ戦略

パス描画の各段階で生成される中間データはキャッシュされ、要素が変更されない限り再利用される:

| キャッシュ | 内容 | 無効化条件 |
|---|---|---|
| OutlineCache | ローカル空間のポリラインまたは三角形 | `geometryHash` またはスケールバケットの変化 |
| StripCache | strip と alpha スロット | 変換の線形部分、サブピクセル位相、`geometryHash` の変化 |
| StampCache | スタンプデータ配列 | セグメント変化 |
| GradientCache | グラデーションGPUリソース | グラデーション設定または `geometryHash` 変化 |

各キャッシュはフィンガープリント（ハッシュ値）ベースのself-validating方式を採用しており、明示的な無効化通知なしにヒット時に自動検証する。詳細は[キャッシュシステム](/devdocs/renderer/caches)を参照。
