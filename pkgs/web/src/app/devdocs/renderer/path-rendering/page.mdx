# パス描画フロー

Paplicoにおけるパス要素（Path）は、3次ベジエ曲線の配列として表現される。本ページでは、このベジエ曲線データがどのようにGPU描画コマンドに変換されるかを、データ構造からシェーダー実行まで順を追って解説する。

> [!NOTE]
> このページは[要素レンダリング](/devdocs/renderer/elements)および[パイプライン概要](/devdocs/renderer/pipeline)の内容を前提とする。

## データ構造

パス要素は `CubicBezierSegment` の配列で構成される。各セグメントは3次ベジエ曲線の4つの制御点を持つ:

| フィールド | 説明 |
|---|---|
| `start` | 開始アンカー（最初のセグメント以外は省略され、前セグメントの `end` を継承） |
| `cp1` | 制御点1。**開始アンカーからの相対オフセット** |
| `cp2` | 制御点2。**終了アンカーからの相対オフセット** |
| `end` | 終了アンカー（ワールド座標） |
| `isMoved` | 新しいサブパスの開始を示すフラグ |
| `isClosed` | サブパスの閉じフラグ |
| `startPressure` / `endPressure` | セグメント始点・終点での筆圧（0-1） |

`cp1` と `cp2` を相対オフセットとして保存する理由は、アンカー点の移動時に制御点が自動的に追従するため、座標変換やアニメーション時の安定性が向上するためである。実際の描画時には `resolveSegment()` でワールド座標に変換される:

```typescript
// cp1: start からの相対 → ワールド座標
cp1_world = { x: start.x + cp1.x, y: start.y + cp1.y }
// cp2: end からの相対 → ワールド座標
cp2_world = { x: end.x + cp2.x, y: end.y + cp2.y }
```

## フラッテニング

フラッテニングとは、ベジエ曲線を十分に細かい直線の列（ポリライン）に近似する処理である。GPU はベジエ曲線を直接ラスタライズできないため、すべてのパス描画はこの段階を経る。

実装は `flattenBezierPath()`（`CanvasLayer.helpers.ts`）にあり、**de Casteljau の再帰二分割法**を使用する:

1. ベジエ曲線の4制御点 (p0, p1, p2, p3) を受け取る
2. 曲線が十分に「平ら」かを判定（制御点が始点-終点の直線からどれだけ離れているか）
3. 平らでなければ、中点で2つのベジエ曲線に分割して再帰処理
4. 平らなら、終点を直線セグメントとして出力

既定の許容度は **0.25**、最大再帰深度は **9** である。どちらもオプションで上書きでき、許容度には下限 `0.01` が適用される。この結果、`number[]` 形式の座標列 `[x0, y0, x1, y1, ...]` が得られる。

筆圧情報が必要な場合は `flattenBezierPathWithPressure()` を使用する。この関数は各分割点でのベジエパラメータ `t` を記録し、セグメントの `startPressure` / `endPressure` から圧力を線形補間して返す。

## Fill: Stencil-Then-Cover

塗りつぶしは **Stencil-Then-Cover** 方式で行う。この方式は自己交差するパスや穴（サブパス）を持つ複雑な形状を正確に処理できる。

### Fan Pass（ステンシル書き込み）

各サブパスに対して:

1. **重心を計算** — サブパスの全頂点の平均座標
2. **三角ファンを生成** — 重心と隣接する2頂点で三角形を構成 (center, v[i], v[i+1])
3. **ステンシルバッファに描画** — 表面向き三角形では `increment-wrap`、裏面向き三角形では `decrement-wrap` を行う。最終的にステンシル値が非ゼロの領域をパスの内側とみなす

### Cover Pass（カラー書き込み）

パス全体のバウンディングボックスを覆うquad（2三角形）を描画する。ステンシルテストを `not-equal`（ステンシル値 ≠ 0）に設定することで、パス内側の領域だけが着色される。

### フリンジAA

Cover Passの後、パス輪郭に沿って1ピクセル幅のフリンジストリップを描画する。輪郭上の頂点は alpha=1.0、法線方向に1px外側の頂点は alpha=0.0 として、エッジのジャギーを滑らかにする。

> [!TIP]
> Stencil-Then-Coverを採用する理由は、earcut等のポリゴン三角形分割アルゴリズムが自己交差パスを正しく処理できないためである。ステンシルバッファを利用すれば、パスの形状に関係なくGPUが正確な塗りつぶし領域を判定できる。

## Stroke: ジオメトリックブラシ

ジオメトリックブラシ（SVGブラシ）によるストロークは `tessellateStroke()` で三角形メッシュに変換される。

### テッセレーション処理

1. **半幅計算** — 各頂点で `halfWidth = baseWidth * 0.5 * (1 - sizeByPressure * (1 - pressure))` を算出
2. **可変幅補間** — `strokeWidths` 配列が設定されている場合、Arc-length parameterizationで各点の左右幅を補間
3. **セグメント構築** — 各辺の方向ベクトル (dx, dy) と法線ベクトル (nx, ny) を計算
4. **三角形化** — 各辺について、法線方向に半幅だけ拡張した2つの三角形を生成
5. **Join処理** — 辺の接続部で `lineJoin` 設定に応じた処理:
   - `round`: 扇形の三角形群で丸く接続
   - `bevel`: 1つの三角形で斜めに接続
   - `miter`: 延長線の交点まで尖らせる（ミターリミット 4.0 超過時はbevelにフォールバック）
6. **Cap処理** — 始点・終点で `lineCap` 設定に応じた処理:
   - `round`: 半円の三角形群
   - `square`: 半幅分の矩形延長
   - `butt`: 延長なし
7. **フリンジAA** — ストローク外周に1pxのフリンジを追加（内側 alpha=1.0、外側 alpha=0.0）

### ダッシュパターン

`applyDashPattern()` がSVG仕様準拠の破線パターンを適用する。フラッテニング済みポリライン上でパターン長を累積し、線分内の正確な位置で補間して分割する。

## Stroke: テクスチャブラシ

テクスチャブラシ（airbrush、pencil等）は `StampGenerator` でスタンプを生成し、`BrushStrokeRenderer` でインスタンスドレンダリングする。詳細は[ブラシレンダリング](/devdocs/renderer/brush)ページを参照。

処理の概要:
1. ベジエ曲線上を Arc-length parameterization で等間隔に走査
2. 各スタンプ位置でベジエ曲線を評価し、座標・回転・筆圧・サイズを算出
3. 全スタンプデータを `Float32Array` にパックしてGPUバッファに転送
4. テクスチャ別にバッチ化し、インスタンスドレンダリングで一括描画

## シェーダー

### Unified Geometry Shader

`unified.wgsl.ts` がストロークとフィルの両方の描画を担当する。

**Vertex Shader:**
1. Storage BufferからElement transform（平行移動・回転・スケール）を読み取り適用
2. オフセット（フリンジAA用）を `1/zoom` でスケーリングして加算
3. ワールド座標をビューポート相対座標に変換し、回転を適用
4. NDC（-1〜1）に正規化して出力

**Fragment Shader:**
- `gradientType` で分岐:
  - `0`: ソリッドカラー
  - `1`: 線形グラデーション — OKLab色空間で知覚的に補間
  - `2`: 放射状グラデーション — 楕円+回転対応
  - `3`: フリーグラデーション — Coons Patchテクスチャサンプリング
- Premultiplied alphaで出力
- クリップマスクがある場合はマスクテクスチャをサンプリングして適用

## キャッシュ戦略

パス描画の各段階で生成される中間データはキャッシュされ、要素が変更されない限り再利用される:

| キャッシュ | 内容 | 無効化条件 |
|---|---|---|
| GeometryCache | フラッテニング結果 | `geometryHash` 変化 |
| StrokeCache | ストローク頂点バッファ | `geometryHash` またはキャッシュキー変化 |
| StencilFillCache | Fan三角形 + フリンジバッファ | `geometryHash` or `transformIndex` 変化 |
| StampCache | スタンプデータ配列 | セグメント変化 |
| GradientCache | グラデーションGPUリソース | グラデーション設定または `geometryHash` 変化 |

各キャッシュはフィンガープリント（ハッシュ値）ベースのself-validating方式を採用しており、明示的な無効化通知なしにヒット時に自動検証する。詳細は[キャッシュシステム](/devdocs/renderer/caches)を参照。
