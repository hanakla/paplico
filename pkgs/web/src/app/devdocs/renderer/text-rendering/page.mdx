# テキストレンダリング

> [!TIP]
> **前提ページ:** [パス描画フロー](/devdocs/renderer/path-rendering)、[エレメントレンダリング](/devdocs/renderer/elements)

Paplicoにおけるテキストレンダリングは、`TextElement` のデータをマルチステージパイプラインを通じてWebGPU描画可能なグリフパスに変換する処理である。WebGPUには文字列を直接描画する仕組みが存在しないため、フォントファイルから各グリフのアウトラインをベクターパスとして抽出し、既存のパス描画パイプラインに流す方式を採用している。

> [!NOTE]
> テキストはテクスチャアトラスではなくパスとして描画される。グリフのパスが `renderPath` に委譲されるため、パスと同じアピアランス（フィル・ストローク・フィルター）を適用できる。通常はグリフごとに1回 `renderPath` を呼ぶ。要素がジオメトリフィルターを持つときは、グリフを連結して1つのパスとして渡す。ジオメトリフィルターはグリフ単位ではなくテキスト全体にかかるものだからである。`3d-rotate` は、テキスト全体で共有する1つの投影を使う。

## モジュール概観

| モジュール | 役割 |
|---|---|
| `TextLayoutEngine` | テキスト内容とスタイルからグリフの配置情報を生成 |
| `TextRenderer` | レイアウト結果をPath形式に変換、キャッシュ管理 |
| `TextElementRenderer` | WebGPUパイプラインへの統合、非同期パスキャッシュ |
| `FontManager` | フォントの読み込み・テキストシェイピング・グリフパス抽出 |
| `GoogleFontsLoader` | Google Fonts APIからのフォント取得・登録 |
| `LocalFontsLoader` | Local Font Access APIによるOSフォント利用 |

## TextLayoutEngine

`TextLayoutEngine` はテキスト内容とスタイル情報を受け取り、各グリフの配置情報（位置・サイズ・回転）を算出するモジュールである。レイアウト処理はCPU上で完結し、GPU描画には関与しない。

### レイアウトモード

書字方向は `layout.writingMode` で、パスへの束縛は `axisBinding` で指定する:

| モード | 指定 | 説明 |
|---|---|---|
| 横書き | `layout.writingMode: "horizontal-tb"` | 左→右に文字を配置、行は上→下に進行 |
| 縦書き（右→左） | `layout.writingMode: "vertical-rl"` | 上→下に文字を配置、列は右→左に進行 |
| 縦書き（左→右） | `layout.writingMode: "vertical-lr"` | 上→下に文字を配置、列は左→右に進行 |
| パスに沿ったテキスト | `axisBinding` (mode: "onPath") | 開いたベジエ曲線パスに沿って文字を配置 |
| エリアテキスト | `axisBinding` (mode: "inShape") | 閉じたパスの内側に文字を流し込む |

`layout` はこのほかに、ボックスの大きさ（`boxWidth` / `boxHeight`）、あふれたときの扱い（`overflow`: `visible` / `hidden` / `ellipsis`）、折り返しの有無（`wordWrap`）を持つ。折り返し位置は `lineBreak.ts` が決める。CJK 文字の間ではどこでも改行でき、行頭禁則・行末禁則に従い、ラテン文字の単語の途中では改行しない。

入口は2つある。`layout()` は1つの `TextElement` をレイアウトする。`layoutFlow()` は、`flow.nextTextElementId` でつながったテキスト要素の連なり（フローチェーン）を一度にレイアウトする。チェーンでは先頭の要素だけが内容を持ち、あふれた文字が次の要素のリージョンへ流れ込む。

### 文字配置フロー

1. **スタイルマージ** — `defaultStyle` と各 `run.style` をマージし、フォントサイズ・ウェイト・色などを決定
2. **フォント読み込み** — `FontManager` 経由でフォントを取得。読み込み失敗時は **Noto Sans JP**（アプリケーション埋め込みのフォールバックフォント）にフォールバック。可変フォントでは、スタイルの `fontWeight` と `fontVariationSettings` から軸の値を求め、その値のインスタンスを使う
3. **テキストシェイピング** — `FontManager` が`@cantoo/fontkit`（OpenType/AATシェイピングを内蔵したフォントエンジン）を使用してテキストをシェイピングし、`ShapedGlyph[]` を返す。シェイピングはグリフID・アドバンス幅・グリフパスを含む
4. **CharOverride適用** — 文字単位のオーバーライド（`kerningAdjust`、`sizeMultiplier`、`baselineShift`、`rotation`、`skewX` / `skewY`、`offsetX` / `offsetY`）を適用
5. **グリフ配置** — レイアウトモードに応じた位置計算とアライメント（`left`、`center`、`right`、`justify`）を適用
6. **バウンズ計算** — インクバウンズ（実際のグリフの描画領域）とフォントメトリクス（ascender/descender）からバウンディングボックスを算出

### 縦書きサポート

縦書きレイアウトでは、OpenTypeの `vert` **GSUB（Glyph Substitution）フィーチャー**（縦書き用のグリフに置き換えるOpenTypeフォント機能）を使用して縦書き用グリフへの置換を行う。

文字は以下の3つに分類される:

| 分類 | 処理 | 対象例 |
|---|---|---|
| rotate | 90度回転して配置 | 括弧 `()[]`、ダッシュ `—` |
| offset | 位置オフセットを適用 | 句読点 `、。` |
| normal | そのまま縦方向に配置 | 漢字、かな、アルファベット |

列は右から左へ進行する（`vertical-rl` の場合）。

ラン単位の `tateChuYoko`（縦中横）を立てると、そのランの文字は縦書きの中で1文字分のセルに横組みで収められる。

### パスに沿ったテキスト

`axisBinding` (mode: "onPath") が指定されている場合、文字は `pathObjectId` の参照先パスの `CubicBezierSegment` に沿って配置される。

1. **パス長の計算** — 20ステップの近似でベジエ曲線のアーク長を算出
2. **文字中心の配置** — 各文字のアドバンス幅の中心がパス上に位置するよう、累積距離で配置座標を決定
3. **接線回転** — 配置座標でのパスの接線角度を算出し、文字にその回転を適用

## グリフパス抽出

フォントファイルからグリフのアウトラインを抽出し、Paplicoのパス形式（`CubicBezierSegment[]`）に変換する処理である。

### fontkitのパスコマンド

fontkitは以下のパスコマンドでグリフアウトラインを表現する:

| コマンド | 説明 |
|---|---|
| `moveTo(x, y)` | 新しいサブパスの開始 |
| `lineTo(x, y)` | 直線セグメント |
| `quadraticCurveTo(cpx, cpy, x, y)` | 2次ベジエ曲線 |
| `bezierCurveTo(cp1x, cp1y, cp2x, cp2y, x, y)` | 3次ベジエ曲線 |
| `closePath()` | サブパスを閉じる |

### 2次→3次ベジエ変換

fontkitの `quadraticCurveTo` は2次ベジエ曲線を返すが、Paplicoのパスデータは3次ベジエ（`CubicBezierSegment`）で統一されている。以下の変換公式で2次を3次に昇格する:

```
cp1 = start + 2/3 * (qcp - start)
cp2 = end   + 2/3 * (qcp - end)
```

ここで `qcp` は2次ベジエの制御点、`start` / `end` はセグメントの始点・終点である。

### Em正規化ストレージ

グリフパスは**Em正規化**（`unitsPerEm` で除算してフォントサイズ非依存にした座標系）で1度だけキャッシュされる。描画時に `fontSize` を乗じて実際のサイズにスケーリングする。これにより、同一グリフを異なるフォントサイズで使う場合もキャッシュを共有できる。

### CubicBezierSegmentへの変換

直線セグメントは退化した3次ベジエとして表現する:

```
// Line as degenerate cubic
cp1 = (end - start) / 3       // relative offset from start
cp2 = -(end - start) / 3      // relative offset from end
```

`cp1` / `cp2` は始点・終点からの**相対オフセット**で格納される。これはPaplicoの `CubicBezierSegment` の共通規約である。

## フォント管理

`FontManager` はフォントの読み込み・テキストシェイピング・グリフパス抽出を一元管理するモジュールである。

### フォント読み込みルート

| ルート | モジュール | 説明 |
|---|---|---|
| Google Fonts | `GoogleFontsLoader` | Google Fonts APIのレスポンスに含まれるウェイト別のフルTTFを取得し、FontManagerに登録。CSS2 APIのサブセット化ではCJKフォントのグリフが欠けるため、サブセットではないファイルを使う |
| ローカルフォント | `LocalFontsLoader` | Local Font Access API経由でOSにインストール済みのフォントを利用 |
| 埋め込みフォールバック | — | Noto Sans JPがアプリケーションに埋め込まれており、他のルートが失敗した場合のフォールバックとして使用 |

### テキストシェイピング

`FontManager` は `@cantoo/fontkit` の `layout()` メソッドを呼び出してテキストシェイピングを実行する。fontkitは自前のGSUB/GPOS・AATシェイパーでグリフID・アドバンス幅を算出する。その結果からグリフパスを抽出し、`ShapedGlyph[]` として返す。合字では1つのグリフが複数の文字を受け持つため、`ShapedGlyph` は元テキスト内の位置（`charIndex`）と受け持つ長さ（`charLength`）を持つ。

### 可変フォント

可変フォントの軸の値は `TextStyle` が持つ。`wght` 軸は `fontWeight` に、それ以外の軸は `fontVariationSettings` に入る。`FontManager.resolveFontForStyle` がスタイルから軸の値を求め、fontkit の `getVariation()` でその値のフォントインスタンスを作る。インスタンスは元のフォントごとにキャッシュされ（最大32件、超えると古いものから捨てる）、シェイピングとグリフパス抽出で共有される。読み込んだフォントが持つ軸は `FontManager.getVariationAxes` で取得できる。

### グリフパスキャッシュ

グリフパスはフォントインスタンスごとの `WeakMap` にグリフIDをキーとしてキャッシュされる。同一フォントインスタンス・同一グリフIDのグリフパスはキャッシュにある限り再抽出されない。パスはEm正規化されているため、フォントサイズに依存しない。1つのフォントインスタンスにつき2,048グリフを上限とし、超えると最も長く使われていないものから捨てる。

## テキストの座標系

| 座標系 | 原点 | Y軸 | 単位 | 用途 |
|---|---|---|---|---|
| Em Space | (0, 0) | 上が正 | 1em = 1.0 | グリフパス（キャッシュ済み） |
| Local | (0, 0) | 上が正 | px | TextLayoutEngine出力 |
| World | キャンバス中心 | 上が正 | px | element.x/y オフセット適用後 |

**座標変換:**
- Em → Px: `value × fontSize`
- Local → World: `+ element.x/y`

| レベル | キャッシュ | 所有者 | キー | ライフタイム |
|---|---|---|---|---|
| L1 | Glyph Path Cache | `FontManager` | フォントインスタンス（`WeakMap`）→ グリフID | フォントインスタンスが生きている間。フォントごとに2,048件のLRU |
| L2 | Layout Cache | `TextRenderer` | element ID。エントリがテキストキャッシュキーを持ち、一致したときだけヒットする | キーが変わると再計算 |
| L3 | Path Cache | `TextElementRenderer` | テキストキャッシュキー | `invalidateTextCache` で無効化。無効化されたエントリは stale キャッシュへ移る |
| L4 | Bounds Cache | — | element ID | テキスト編集・移動時に無効化 |

L1のGlyph Path Cacheのエントリは不変（immutable）である。同一フォントインスタンス・同一グリフIDのグリフ形状は変化しないため、内容の無効化は必要ない。エントリが消えるのは、LRUの上限を超えたときと、フォントインスタンスが解放されたときだけである。

テキストキャッシュキーは `TextRenderer.computeTextCacheKey` が作る文字列である。要素ID、内容、既定スタイルのフォント関連の値（ファミリー、ソース、可変軸、サイズ、ウェイト、スタイル、字間、行の高さ）、`layout`、軸バインディングの情報からなる。軸バインディングの情報には、束縛先パスのジオメトリのリビジョンと、要素の位置・変形が入る。フローチェーンに属する要素では、先頭要素の内容とスタイル、各メンバーの `layout` と軸バインディングもキーに入る。要素のワールド位置は、軸バインディングが無ければキーに入らない。位置は描画時にローカルのグリフパスをずらして適用するためである。

## 非同期レンダリングパターン

テキストレンダリングでは、レイアウト計算とグリフパス抽出が数十ミリ秒を要しうる（特にCJKテキストでは文字数が多く、フォントパースの負荷が高い）。レンダリングフレームをブロックしないよう、非同期ファーストのレンダリングパターンを採用している。

1. `renderText()` が呼び出され、テキストキャッシュキーで `pathCache` をチェック
2. **キャッシュヒット**: キャッシュ済みパスで即座に `renderPath()` を呼び出して描画。その要素の stale エントリは消す
3. **キャッシュミス**: `requestTextPathCache()` を非同期で発火する。`stalePathCache` に同じキー、または同じ要素IDの古いエントリがあれば、それで描画してからreturnする。無ければ何も描かずにreturnする
4. **非同期解決**: パス抽出が完了すると `pathCache` に格納し、再レンダリングを要求
5. **次フレーム**: キャッシュヒットとなり、新しいグリフパスが描画される

stale キャッシュは、ちらつきを防ぐためにある。`invalidateTextCache` で `pathCache` から外されたエントリは `stalePathCache` に移る。新しいパスが届くまでのフレームは、その古いパスで描かれる。

`pendingPathCacheKeys` セットが重複リクエストを防止する。同一要素に対する `requestTextPathCache()` が複数フレームにわたって重複発火されることを防ぎ、不要な計算を回避する。

## データ構造

テキストレンダリングに関連する主要な型定義:

### TextElement

```typescript
interface TextElement extends ArtObject {
  type: "text"
  x: number                     // world coordinates
  y: number
  content: TextContent
  defaultStyle: TextStyle
  layout: TextLayout
  axisBinding?: TextAxisBinding // pathObjectId で軸パスを参照
  flow?: TextFlow               // フローチェーンのリンク
  clipPathId?: string | null
}

interface TextLayout {
  writingMode: "horizontal-tb" | "vertical-rl" | "vertical-lr"
  boxWidth: number | "auto"
  boxHeight: number | "auto"
  overflow: "visible" | "hidden" | "ellipsis"
  wordWrap: boolean
}

type TextAxisBinding =
  | { mode: "onPath"; pathObjectId: string; startOffset: number; offset?: number;
      alignment: "left" | "center" | "right"; offsetDistance: number;
      orientation: "upright" | "rotate" }
  | { mode: "inShape"; pathObjectId: string; inset?: number }

interface TextFlow {
  nextTextElementId?: string    // あふれた文字の流し込み先
}
```

### TextContent

```typescript
interface TextContent {
  paragraphs: TextParagraph[]
  charOverrides?: CharOverride[]
}
```

### TextParagraph / TextRun

```typescript
interface TextParagraph {
  runs: TextRun[]
  alignment: "left" | "center" | "right" | "justify"
  lineHeight: number            // 1.0 = 100%
  indent: number                // first-line indent (px)
  spacing: { before: number; after: number }
}

interface TextRun {
  text: string
  style: TextStyle
  charOverrides?: CharOverride[]
}
```

### TextStyle

```typescript
interface TextStyle {
  fontFamily: string
  fontSource: FontSource
  fontSize: number              // px
  fontWeight: number            // 可変フォントでは wght 軸の値
  fontVariationSettings?: Record<string, number> // wght 以外の可変軸
  fontStyle: "normal" | "italic" | "oblique"
  fill: FillColor | null
  stroke?: StrokeColor | null
  strokeWidth?: number
  underline: boolean
  strikethrough: boolean
  letterSpacing: number         // em
  lineHeight?: number
  baselineShift: number         // px
  tateChuYoko?: boolean         // 縦中横
  openTypeFeatures?: Record<string, boolean>
}
```

### CharOverride

```typescript
interface CharOverride {
  charIndex: number
  kerningAdjust?: number      // inter-character spacing adjustment (em)
  sizeMultiplier?: number     // relative size multiplier (1.0 = default)
  baselineShift?: number      // vertical offset from baseline (px)
  rotation?: number           // per-character rotation (degrees)
  skewX?: number              // horizontal shear angle (degrees)
  skewY?: number              // vertical shear angle (degrees)
  offsetX?: number            // visual offset (px, element-local axes, Y-up)
  offsetY?: number
}
```

### LayoutedChar

```typescript
interface LayoutedChar {
  char: string
  charIndex: number           // index within the content
  runIndex: number
  paragraphIndex: number
  x: number
  y: number
  rotation: number            // radians, used for path placement
  fontSize: number
  font: LoadedFont
  glyphPath: CubicBezierSegment[]
  advanceWidth: number
  kerningOffset: number
  sizeScale: number
  override?: CharOverride
  tateChuYoko?: boolean
  synthetic?: boolean         // ellipsis など、内容に存在しない合成グリフ

}
```

interface LayoutResult {
