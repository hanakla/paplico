## どこで使われている？

ペンタブで描いた線って、**1 秒間に 100 個以上の点** をブラウザに送ってくる。これをそのまま保存すると重い。1 本のベジェに **要約** すれば、データはずっと小さくなって、後の編集 (引っ張る、伸ばす) もしやすくなるよ。

Paplico の `processStroke` の最終段階がまさにこれ。実装では Schneider's algorithm を元に、誤差が大きいところで分割しながら複数のベジェにしている。この章では最初の 1 歩として、**1 本の cubic にフィットする部分**だけを作るよ。

## どうやって動くのか — ステップで見ていこう

### ステップ 1: 端点と接線方向は決まる

ベジェ曲線で、**最初の点 p0 と最後の点 p3** は、点列の両端に固定するよ。**自由に動かせるのは p1 と p2 の 2 つだけ**。

さらに、両端の接線方向 (曲線の出口・入口の向き) は、**点列の隣の点との差分** から決められる。

```
p0     = points[0]
p3     = points[N-1]
tHat0  = normalize(points[1]   - points[0])     ← 入口の向き
tHat3  = normalize(points[N-2] - points[N-1])   ← 出口の向き
```

p1 は p0 から **tHat0 方向にどれだけ進むか** だけが自由。p2 も同じく p3 から **tHat3 方向にどれだけ進むか** だけ。

つまり、決めるのは **2 つの距離 (α1, α2) だけ**！

まずは雑に `α1 = α2 = |p3 - p0| / 3` と置ける。これでも曲線にはなるけれど、点列全体を見ると山の高さや左右の張りが少しズレる。ここから **点列全体を見て α1 と α2 を直す** のが、この章の主役だよ。

### ステップ 2: 各点に t をふる (chord-length parameterization)

「点 i は曲線のどの場所にいる？」を **0 〜 1 の数 t** で表現する。一番素直なのは、**点同士の距離を足していった割合**。

```
total = points間の距離の合計
ts[0] = 0
ts[i] = (0..i 番目の) 累積距離 / total
```

これで `ts[0] = 0`, `ts[N-1] = 1` になり、間の点もちょうど距離の比例で並ぶよ。

### ステップ 3: 線形最小二乗で α1, α2 を解く

ベジェの式に Bernstein 基底を入れると:

```
B(t) = B0(t) p0 + B1(t) p1 + B2(t) p2 + B3(t) p3
```

p1 = p0 + α1·tHat0、p2 = p3 + α2·tHat3 を入れて整理すると、まず「α が 0 のときの曲線」は:

```
base_i = (B0(t_i) + B1(t_i)) p0 + (B2(t_i) + B3(t_i)) p3
```

ここから `B1(t_i) α1 tHat0` と `B2(t_i) α2 tHat3` のぶんだけ曲線がふくらむ。各点 P_i との **誤差** は:

```
err_i = P_i - base_i
       - B1(t_i) α1 tHat0
       - B2(t_i) α2 tHat3
```

これの **二乗和** を最小化する α1, α2 を求めるのが線形最小二乗。**2 個の未知数だから 2 元連立方程式** ですぐ解けるよ。

```
[ Σ B1² (tHat0·tHat0)   Σ B1 B2 (tHat0·tHat3) ] [ α1 ]   [ Σ B1 (e·tHat0) ]
[ Σ B1 B2 (tHat0·tHat3)  Σ B2² (tHat3·tHat3)  ] [ α2 ] = [ Σ B2 (e·tHat3) ]
```

行列式 `det = c00 c11 − c01²`。`det ≠ 0` なら 2 × 2 のクラメル法で解ける。

### ステップ 4: 異常値のフォールバック

α1 や α2 が **0 以下** や **異常に小さい値** になることがあるよ (点列が直線に近すぎる場合など)。そのときは、**ヒューリスティックなデフォルト**として `α = |p3 − p0| / 3` を使うのが定番。

## 数学のところ（読み飛ばしOK）

<details>
<summary>正規版 Schneider's Algorithm</summary>

Paul Schneider が 1990 年に出した方法は:

1. **chord-length parameterization** で初期 `t_i` を計算
2. **線形最小二乗** で α1, α2 を解く (この章で実装するやつ)
3. **誤差** が許容を超えていたら、誤差最大の点で曲線を分割し、左右別々にフィッティング (再帰)
4. 各分割した区間で **Newton-Raphson 反復** で `t_i` を曲線に正確に投影しなおして再フィット

Newton 反復は「いまのベジェ曲線に一番近い場所へ `t_i` を置きなおす」処理だよ。第6章の最近点探索に近い話なので、この章では発展として眺めるだけで OK。Paplico の `strokeFitting.ts` の `fitCubicBeziers` がこの流れを本格的に使っているんだ。

</details>

正しく書けたら、山の高さと左右の張りが見て分かるくらい改善する。ノイズまで全部追いかける必要はないよ。1 本のベジェで「点列の真ん中」を通れたら成功！

## 合格の目安

- 最初の starter: 青い曲線は出るけれど、灰色の点列の山より少し浅く見える
- 解答例: 青い曲線が灰色の点列の中心を通り、p1 / p2 のハンドルが正しい長さまで伸びる
- 目安の誤差: starter の RMS 誤差はだいたい 20px 前後、解答例は 4px 前後まで下がる

ここで見たいのは「完全一致」ではなく、**固定ハンドル距離から、点列全体を使ったハンドル距離へ改善すること**だよ。
