# 第1章: 座標系の話 — Screen と World

## この章でできるようになること

- 画面 (Screen) の点と、世界 (World) の点をお互いに変換できるようになる
- なぜ Y 軸の向きを反転するのか、自分の言葉で説明できる
- 拡大・縮小 (zoom) を含めた座標変換が頭の中で描けるようになる

## どこで使われている？

ユーザーがマウスを「カチッ」と押した瞬間、ブラウザが教えてくれるのは **画面 (Screen) の座標** だけ。でも絵のデータとしては、絵の真ん中を基準にした **世界 (World) の座標** で保存しないと困る (画面サイズが変わるたびに絵が動いてしまうからね)。

だから、お絵かきツールは入口のところで **Screen → World** の変換を必ず通る。逆に、データを画面に表示するときは **World → Screen** に戻すよ。Paplico のすべてのツール (ペン、選択、塗り、テキスト) はここを必ず通るんだ。

### ステップ 2: ズーム倍率で割る

絵を拡大表示しているとき、画面の 100 ピクセルは絵の世界の 100 とは限らないよね。ズームが 2 倍なら、画面で 200 ピクセル動いた点は、絵の世界では 100 しか動いていない。

だから **画面のズレをズーム倍率で割って** 絵の単位に直すよ。

```
画面の差 ÷ zoom = 世界の差
```

### ステップ 3: Y 軸を反転する

最後に Y の向き。Screen は下向きが「+」、World は上向きが「+」。**Y にだけマイナスをつける** と、向きが入れ替わるよ。

3 つのステップをつなげると、こうなるよ:

```
worldX = (screenX − 画面幅/2) ÷ zoom + viewport.x
worldY = −(screenY − 画面高/2) ÷ zoom + viewport.y
```

`viewport.x` と `viewport.y` は「いま画面の真ん中で見ている世界の場所」。最後に足すことで、画面の外の点も正しく扱えるようになるよ。

## 数学のところ（読み飛ばしOK）

<details>
<summary>行列で書くと…</summary>

3 つのステップは、3 つの 2D 変換の合成と見ることもできるよ:

1. 平行移動 (− 画面の中心)
2. スケール (1/zoom × Y 反転)
3. 平行移動 (+ viewport)

行列で書くと:

```
[ 1/zoom    0       vx ]   [ 1   0   −w/2 ]   [ sx ]
[   0    −1/zoom    vy ] · [ 0   1   −h/2 ] · [ sy ]
[   0      0        1  ]   [ 0   0     1  ]   [  1 ]
```

逆向き (World → Screen) は、この合成行列の逆行列だよ。

</details>

## 実装してみる

`screenToWorld` と `worldToScreen` を書いてみよう。Canvas をクリックすると、青い点（4 か所のテスト点）が表示されるよ。**正しく書けたら、4 か所が上下左右にきれいに散らばるはず**。間違っていると、点が 1 か所に固まったり、画面の外に飛んでいったりするよ。
